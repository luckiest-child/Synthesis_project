Web Accessibility Awareness

Everyday design decisions create real barriers.

Web accessibility is not an abstract compliance checklist. Lumina explores how specific design choices prevent people with disabilities from accessing information, completing tasks, and participating independently online.

Areas of Focus

Accessibility Barriers & Challenges

4 Core Areas
01 / Visual

Visual Accessibility

People with blindness, low vision, or color vision deficiencies face immediate barriers when interfaces depend on visual information. Unlabelled graphics, faint text contrast, and missing alternative descriptions make content difficult or impossible to perceive.

02 / Auditory

Hearing Accessibility

People who are deaf or hard of hearing miss essential announcements, instructions, and discussions when multimedia relies solely on sound. Without synchronized captions, transcripts, or visual cues, vital information is withheld.

Captions & Media Alternatives Learn about this →
03 / Motor

Motor Accessibility

People with tremors, arthritis, or paralysis, as well as keyboard-only navigators, struggle with interfaces that demand pixel-perfect pointer accuracy. Microscopic targets, missing focus indicators, and erratic tab orders cause severe physical fatigue and errors.

Keyboard Flow & Target Size Learn about this →
04 / Cognitive & Language

Cognitive & Language Accessibility

Confusing instructions, cluttered layouts, artificial countdown timers, and dense bureaucratic jargon place heavy demands on mental processing. Clear structure and plain language ensure information can be understood by neurodivergent users and diverse audiences alike.

Core Philosophy

Design Decisions Shape Inclusion

Barriers on the web are rarely intentional, but they are almost always the direct consequence of developer and designer choices. When we build interfaces assuming that all visitors possess standard vision, hearing, dexterity, and processing speed, we inadvertently exclude millions from education, public services, and daily life.

Lumina is built on the premise that encountering these barriers firsthand fosters informed empathy and practical competence. Accessible design is not about limiting creativity; it is about ensuring that what we create is usable by everyone.

Project Context

About Lumina

Lumina is an academic mini synthesis project built using standard HTML5, CSS3, and vanilla JavaScript. Its purpose is to demonstrate introductory front-end web development principles while examining how digital barriers affect people in everyday life.

Accessibility Commitment: This website is built to conform to WCAG 2.1 Level AA recommendations, featuring semantic HTML landmarks, high text contrast (>15:1), full keyboard accessibility, visible focus indicators, and responsive layouts that adapt to any screen size.
